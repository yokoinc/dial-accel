# DialAccel

*[Version française](README.fr.md)*

Accelerated dial scrolling for the **MX Creative Console**, on Windows.

Scrolls through slices in OHIF — or any keyboard-driven viewer — by sending
up/down arrow keys: the faster you turn the dial, the longer the burst. The
Logitech counterpart of the Stream Deck plugin
[yokoinc/elgato-dial-scroll](https://github.com/yokoinc/elgato-dial-scroll).

## How it works

The console does not report one detent at a time: its firmware already batches
detents according to rotation speed and sends a `tick` between 2 and 12. The
plugin calibrates its own "one detent" unit on the smallest `tick` it has seen,
then applies a logarithmic gain:

```
keystrokes = detents × (1 + gain × ln(detents))
```

Logarithmic rather than exponential: it bites from the very first detents, then
flattens out instead of running away. At the chosen gain (0.6), a rotation of 1
to 6 detents yields 1, 2, 3, 4, 5, 7, 10, 12 keystrokes.

Keystrokes are delivered through Win32 `SendInput`, called straight from Node
via [koffi](https://koffi.dev/). No child process, no script — one syscall per
event.

## Install the packaged plugin

Download [`DialAccel.lplug4`](DialAccel.lplug4) and double-click it: Options+
picks it up and installs it. If nothing happens, the file is a plain zip —
extract its contents into `%LOCALAPPDATA%\Logi\LogiPluginService\Plugins\DialAccel`
and restart the service.

The `nodejs22` junction described below is required either way.

## Build from source

```
npm install
npm run build:pack
```

Then copy the contents of `dist/` into:

```
%LOCALAPPDATA%\Logi\LogiPluginService\Plugins\DialAccel
```

and restart the Logi Plugin Service:

```
Stop-Process -Name LogiPluginService,LogiPluginServiceExt -Force
Start-Process 'C:\Program Files\Logi\LogiPluginService\LogiPluginService.exe'
```

The service never reloads a plugin while running, so this restart is mandatory
after every build.

`npm run link` also exists, but only creates a symlink to `dist/` — handy while
developing, unsuitable for production: deleting the development folder would
break the plugin.

## Two traps that cost hours

**1. The runtime is called `nodejs22`, not `nodejs`.**
The scaffold generated by `@logitech/plugin-toolkit` 0.1.1 writes
`pluginRuntime: nodejs` into `package/metadata/LoupedeckPackage.yaml`. Logi
Plugin Service 6.4 rejects that value. Fixed here — do not regenerate the
scaffold over it.

On top of that, the service downloads its Node host into `PluginHosts\node22`
but looks for it under `nodejs22`. The junction has to be created once:

```
$h = "$env:LOCALAPPDATA\Logi\LogiPluginService\PluginHosts"
New-Item -ItemType Junction -Path "$h\nodejs22" -Target "$h\node22"
```

Without it the log reads `Plugin runtime 'NodeJs22' not yet installed`.

**2. Options+ applies a different profile per application.**
The Dialpad follows the active application. An action assigned in the default
profile will not run inside Edge. The profile tabs sit at the top of the
customisation screen — assign in the one for the application you actually use.

Decisive check: if the plugin logs nothing while you turn the dial, another
profile is active.

## Tuning

`gain`, at the top of [`src/accelerated-dial.ts`](src/accelerated-dial.ts).
Higher is snappier, `0` makes scrolling strictly proportional. The Logi SDK
0.1.1 exposes no settings panel, so changing it means rebuilding.

## Troubleshooting

The plugin log is the only source of truth:

```
%LOCALAPPDATA%\Logi\LogiPluginService\Logs\plugin_logs\DialAccel.log
```

It only handles ASCII — accented characters come out as mojibake. The labels
shown in Options+, on the other hand, must keep their accents: its action search
is accent-sensitive.

## Limitations

The Node SDK 0.1.1 is beta and offers no settings panel, no touch-strip action
and no per-application filter. The large central dial forces its on-screen
overlay whatever action you put on it; the roller at the top right does not.
